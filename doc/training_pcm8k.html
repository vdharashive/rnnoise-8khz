Training RNNoise for 16‑bit PCM @ 8 kHz

RNNoise now accepts a compile-time sample rate override via the RNNOISE_SAMPLE_RATE macro (48 kHz by default, 8 kHz supported). The FFT tables are dispatched through src/rnnoise_tables.c, which includes either rnnoise_tables_48k.c or rnnoise_tables_8k.c. The demo client now queries rnnoise_get_frame_size(), and the feature extractor scales its RIR handling to the configured frame length. The steps below document how to leverage these changes to train and deploy a narrowband model while reusing the existing 48 kHz datasets.

Prerequisites

  • SoX (or an equivalent resampler) for converting the provided 48 kHz speech/noise corpora to 8 kHz.
  • Python 3 with PyTorch (used by torch/rnnoise/train_rnnoise.py).
  • A recent C toolchain (GCC/Clang) for building RNNoise.

1. Prepare 8 kHz training audio

Start from the standard speech/noise archives referenced in datasets.txt (or tts_speech_48k.sw / background_noise.sw). Convert them to single-channel 16‑bit PCM at 8 kHz: 

sox speech_48k.sw   -r 8000 -b 16 -c 1 speech_8k.pcm
sox background.sw   -r 8000 -b 16 -c 1 noise_bg_8k.pcm
sox foreground.sw   -r 8000 -b 16 -c 1 noise_fg_8k.pcm

(Downsample any RIRs that you plan to use as well; they are stored as 32‑bit floats, so sox -t f32 -e float works.)

2. Build the 8 kHz toolchain

Reconfigure RNNoise with the sample-rate override. The dispatcher in src/rnnoise_tables.c automatically selects the correct FFT tables. 

cd /home/ki0980/workspace/rnnoise
CPPFLAGS="-DRNNOISE_SAMPLE_RATE=8000" ./configure
make clean
make -j$(nproc)

The rebuilt dump_features, rnnoise_demo, and library APIs now work on 80-sample (10 ms) frames. You can confirm by running ./examples/rnnoise_demo against an 8 kHz PCM clip.

3. Generate training features

Use the rebuilt dump_features binary on the downsampled corpora: 

./dump_features speech_8k.pcm noise_bg_8k.pcm noise_fg_8k.pcm \
               features_8k.f32 200000
# or scripts/dump_features_parallel.sh if you need concurrency

The feature layout (98 floats per frame) is unchanged, so all PyTorch tooling continues to work.

4. Train the network

Point the training script at the new feature file and choose a suffix that reflects the narrowband model: 

python3 torch/rnnoise/train_rnnoise.py \
        features_8k.f32 runs/8k_model --suffix _8k --epochs 200

Monitor the loss curves as usual (roughly 75k weight updates are still a good rule of thumb).

5. Export weights and rebuild

Convert the checkpoint to C sources and copy them into src/: 

python3 torch/rnnoise/dump_rnnoise_weights.py --quantize \
        runs/8k_model/checkpoints/rnnoise_8k_200.pth rnnoise_8k_c
cp rnnoise_8k_c/rnnoise_data.c rnnoise_8k_c/rnnoise_data.h src/

Rebuild (still with RNNOISE_SAMPLE_RATE=8000) and install or package the resulting library.

6. Runtime verification

Denoise an 8 kHz PCM file with the updated demo program: 

./examples/rnnoise_demo noisy_8k.pcm denoised_8k.pcm

Integrators can call rnnoise_get_frame_size() to discover the frame length (80 samples for 8 kHz).

Appendix

  • If you ever experiment with other sample rates, run gcc ... src/dump_rnnoise_tables.c with the desired RNNOISE_SAMPLE_RATE and drop the generated file in src/rnnoise_tables_<rate>.c.
  • The feature extractor now scales its RIR tapering window with FRAME_SIZE. Existing scripts do not require changes.
  • Only the 48 kHz and 8 kHz band layouts are shipped. Other sample rates will trigger a compile-time error until new tables are generated.
